# 计算与审计规则

## 1. 证据优先级

正式费率表和现金价值表优先于宣传页；保险责任以正式条款为准。投保计划书可以证明特定方案，但不能替代条款定义。每个数值至少保留文件位置、页码、表头、行标签、列标签及 SHA-256。

材料中产品名称、版本、交费期间或保障方案不一致时停止计算。不要混用同系列不同版本的数据。

## 2. 单位审计

先识别表头，再选择 `basis`。常见的两种费率方向互为倒数，误判会造成千倍或更大的偏差：

- 每千元基本保额的年交保费：`基本保额 = 保费 / 费率 × 1000`。
- 每千元年交保费对应基本保额：`基本保额 = 保费 / 1000 × 费率`。

现金价值同样要区分“每千元基本保额”和“每千元年交保费”。脚本只检查文字口径是否一致，不会根据结果大小自动猜测或改小数点。

如原始材料本身存在标题矛盾，记录 `unit_override_reason` 并把输出视为暂定。暂定产品不得参加任何相对排名。

## 3. 保单年度与现金流

- 第一期年交保费发生在 `t=0`。
- 第 2 至 N 期保费发生在 `t=1` 至 `t=N-1`。
- 第 Y 保单年度末退保现金价值发生在 `t=Y`。
- 第 Y 年末累计已交保费为 `年交保费 × min(Y, 交费年数)`。
- `Y < 交费年数` 为交费期间；`Y >= 交费年数` 为交费完成。
- 默认第 Y 保单年度末到达年龄为 `投保年龄 + Y - 1`。如条款定义不同，必须用 `entry_age_plus_year` 显式声明。

保证退保 IRR 解下面的年度现金流方程：

```text
0 = Σ CF_t / (1 + IRR)^t
```

现金流只包括截至退保年度实际应交保费和该年度保证现金价值。脚本使用确定性二分求根，不依赖第三方库。

## 4. 身故保险金

先按保单年度判断责任阶段，再按到达年龄选择给付比例，最后执行条款规定的取大、取小或加总。计算轨迹必须保留每个分支数值，以及 `max`/`min` 最终选择的分支。

普通身故默认不包含航空、公共交通、意外或特定疾病额外给付。只有用户明确比较对应情景，且输入定义了匹配的 `additive_benefits.when.scenario`，才加入附加金额。

身故杠杆为：

```text
身故保险金 / 截至该年度累计已交保费
```

它是保障强度指标，不是收益率。不要把身故保险金代入退保 IRR，也不要用必然发生的语气描述或有身故给付。

## 5. 红利

- 保证红利：只有合同明确保证时才录入；普通分红险通常为 0。
- 演示红利：来自正式利益演示，只能单列低、中、高等情景并标注非保证。
- 实际红利：来自保险公司已经公布的该保单/年度红利通知；未取得时为未知。
- “每千元累计增额红利对应的现金价值/保险金额”是换算系数，不代表客户已经获得该数额红利。

任何非保证或未知红利都不得进入保证现金价值、回收率或保证退保 IRR 排名。

## 6. 相对排名

只有险种、币种、年龄、性别、体况、交费期、年交保费、保障方案及比较年度一致的产品才能同组排名。资料缺失或暂定的产品退出对应指标。

分别对现金价值、累计保费回收率、保证退保 IRR、普通身故保险金和身故杠杆排序，不进行主观加权。并列值使用相同名次。

“窗口领先”须同时满足：

1. 同组至少有两只产品。
2. 所有产品在声明的每个主要指标上都有正式数据。
3. 唯一一只产品在全部主要指标上均列第一。

结论必须同时写出具体保单年度、利益口径和指标集合，并明确不得外推为全周期“综合领先”。不满足时写明“各有取舍”或“资料不足，无法判断”，不得硬给总冠军。

## 7. 报告边界

报告应说明数值精度取决于原表精度，正式承保金额、舍入、加费、职业类别、健康核保和红利分配以保险公司正式计划书与合同为准。结果用于核算复核，不构成保险、法律或投资建议。

## 8. 年金效率与长寿保障

- 年金效率只使用逐年列明的保证领取，不把演示红利或未兑现增额红利混入。
- “保证领取现金流 IRR”只包括截至比较年度的已交保费与保证领取，不含退保价值；它与保证退保 IRR是不同指标。
- “仅靠保证领取回本年度”按累计净现金流首次不低于0判断。
- 长寿尾部给付按显式 `longevity_test_age` 及逐年保证领取表加总。给付表没有覆盖测试年龄时不得计算；未覆盖合同终止年龄时必须标记为部分给付表，不得解释为完整终身尾部价值。
- 终身领取、保证领取年数和合同终止年龄属于不同概念，必须分列。

## 9. 合同选择权价值

- 功能存在不等于有可量化正价值；保单贷款还伴随利息、偿还及未偿贷款扣减。
- 未提供显式增量现金流与折现率时，只报告条款可用性、最大比例和已知成本，不计算NPV。
- 显式情景NPV只回答该客户情景下的增量价值，不代表选择权的普遍市场价值。
- 减保、贷款、减额交清等互斥或相互影响的选择权不得简单相加。

## 10. 压力测试

默认压力审计是“零分红、按保证现金价值提前退出”，因为它可以被正式现金价值表复核。随机生成的资产收益、准备金充足率、ALM缺口或VaR不得进入产品评级；如需公司层面的压力测试，必须另行取得资产、负债、再保险和偿付能力数据，并与产品合同评价分开。
